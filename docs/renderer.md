# Renderer conventions

The renderer is React with React Aria Components ([ADR-0021](adr/0021-use-react-aria-components-for-the-electron-renderer.md)). Its page is `desktop/src/renderer/index.html` and its modules are in `desktop/src/renderer/react/`, organized by functionality.

- **Controllers:** transient view and operation state lives in framework-free modules that expose `subscribe` and a snapshot, as `app-controller.ts` and the controllers it composes do; views read them with `useSnapshot`, or one value with `useSnapshotValue`. Test a controller without a DOM where you can.
- **React Compiler:** components are compiled by Bun's React Compiler ([ADR-0026](adr/0026-compile-the-renderer-with-the-react-compiler.md)), and the tests run them compiled too. A callback must not read through a value that may be undefined at render, as `() => close(outcome!.id)` does: the compiler compares what a callback reads at every render, so guard inside it, as `if (outcome) …` does. Keep rendering pure: read a value that changes outside React, such as a loaded cache or the clock, through `useSyncExternalStore`, as `useIconImage`, `useIconCatalog`, and commit ages do, never by forcing a re-render, because a compiled component keeps a value until its inputs change.
- **Large lists:** a column can show hundreds of files, so its file lists and its diff column's files are memoized, and a snapshot keeps an unchanged item's object (the inspection copies each diff only when it changes). Context values are memoized for the same reason, and the row marking the diff column's top file is marked from outside the rows' render. Only what is near the column's view is drawn. File lists are virtualized by React Aria's `Virtualizer` while they scroll with their column, with rows a little past the view drawn too, because the column's arrow keys step through drawn rows; code that needs a list's rows in order reads them from its data, not the DOM. A diff column file draws its toolbar's controls once it nears the view, and a diff draws, and is highlighted, only near the view; elsewhere a spacer holds its place. Choosing a file glides the diff column to it on a spring that measures the file's place each frame, as Pierre's CodeView does, so diffs drawing above it can't make it land short; while the glide is more than a screen away, the files it passes draw nothing.
- **The kit:** React Aria's vanilla CSS starter components live in `react/ui/`, copied from adobe/react-spectrum at `d3b2bd2` (Apache 2.0). Its README lists every local change; fix kit bugs there and add them to the list, so upstream updates can be compared against the pinned commit. Build views from the kit's components; where the kit has no component at Laneway's density or with the behaviour needed, build one from React Aria Components with CSS that uses only the theme's variables.
- **Colours:** set only in Laneway's theme file, `react/theme.css`, which overrides the kit's variables under `:root:root`. `--tint` is Laneway's amber, and accent fills take dark ink. The repository panel stays dark in both appearances by redefining those variables on the panel. Laneway's own CSS uses the variables, never literal colours; `bun run lint` checks this with stylelint. The kit's own stylesheets keep their upstream colours.
- **Appearance:** the main process sets Electron's `nativeTheme.themeSource` from the appearance setting, so the kit's `prefers-color-scheme` rules follow it without edits. The window's background and title bar overlay can't read the stylesheets, so `main/window-colors.ts` repeats the header's colours, and `react-renderer-styles.test.ts` checks that they still match.
- **CSP:** plain stylesheets only. `meta#react-aria-pressable-style` with its rule in the page CSS stops React Aria's one inline style. Only the development server's copy of the page relaxes `script-src`, adding `blob:` for Bun's hot updates and the hash of the one inline script it adds ([ADR-0027](adr/0027-build-and-serve-the-desktop-app-with-bun.md)). `script-src` adds only `'wasm-unsafe-eval'`, which compiles WebAssembly but evaluates no script, for Pierre's Highlights. Keep `style-src 'self'` and `script-src 'self' 'wasm-unsafe-eval'` unchanged.
- **Density:** commit rows are 32px, file rows 28px, repository rows 40px (36px collapsed) with 28px tiles. Dense collections are React Aria GridLists of `DenseRow`s sharing one row style; the kit's GridList is a card grid.
- **Activation:** React Aria's press timing applies throughout: collection items select and menus open on pointer down, and buttons act on release, which leaves native drags free to start from a row. A row that moves or copies its changes drags from anywhere but its controls and a diff open in it; a control that names the row, such as a commit's subject or a branch's name, takes `data-drags-row` and drags it too.
- **Text selection:** the column row doesn't select text, so a drag can never carry a selection across a column; diffs and commit messages opt back in with `user-select: text`.
- **Tooltips:** every icon-only control has the kit's `Tooltip` naming it, as `IconButton` does. Anything else that explains itself on hover, such as a truncated path or why a control is disabled, wraps in `Hint` (`controls.tsx`) rather than taking a `title`: the browser shows a title over every descendant without one, so a header's or row's covered its buttons'. A hint gives way to the controls and hints inside it, and to a group of controls marked `data-controls`, gaps included, as a column header's buttons are. It waits for the pointer to settle and shares React Aria's tooltip timing, so only one tooltip shows at a time.
- **Row menus:** a `DenseRow` takes its menu items once. Right-click opens them at the pointer, and Shift+F10 under the row, through the app's one `ContextMenuHost`; the same items appear in the row's hover menu button. The host sits outside every list, because a menu rendered inside a row passes its focus events to the list through React's portal bubbling.
- **Dialogs** are the kit's `Modal` and `Dialog`, open while their controller says so. Escape and Cancel go through the controller, which can keep a dialog open while Git runs. Forms use the kit's `Form` and `TextField`, and a failure shows in the form as an alert that takes focus.
- **Destructive actions** apply immediately with an Undo toast (the kit's toast with an `action`), never a confirmation dialog. The one exception is removing a worktree with Working Changes, which asks whether to keep them. An operation's toast (`offerUndo` in `app-controller.ts`) undoes the Operation History's latest operation, so it goes as soon as another operation starts.
- **Icons** are Tabler's React components (ADR-0024), wrapped by `tablerIcon()` in `ui/icons.tsx` so they are hidden from assistive technology by default; the kit's CSS targets their `tabler-icon-<name>` classes. Repository Icons come from the full outline catalogue in `icon-catalog.ts`, loaded on first use.
- **Tests:** DOM tests run React on Happy DOM over the fakes in `test/renderer-fixtures.ts`, installed with `installReactDom` from `test/react-dom.ts` before importing views. Query roles and labels rather than markup. React Aria acts on pointer presses, so tests press with pointer events rather than `click()`. Assert on elements through booleans, as in `expect(a == b).toBe(true)` and `expect(x == null).toBe(true)`: a failing Bun matcher given a Happy DOM element serializes the whole document, and with an app running, `toBeNull()` then passes. What only a real window shows (layout, colours, and the CSP) belongs in the Electron tests, such as `react-renderer-styles.test.ts`, which drive the built app.
