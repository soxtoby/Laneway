# Highlight diffs with Pierre's Highlights

Diffs and conflicts are highlighted by `@pierre/highlights`, the WebAssembly highlighter that `@pierre/diffs` 1.6 offers as its `highlights` backend, instead of Shiki with its JavaScript regular-expression engine. On Laneway's own TypeScript it tokenizes about 130 times faster: a 9,000-line diff drew highlighted in about 150ms where Shiki held the renderer for about 900ms. Its languages are compiled in, so nothing loads per language. Pierre runs one kind of highlighter per page, so diffs and conflict resolution choose it together, and both fall back to Shiki's JavaScript engine wherever WebAssembly can't compile (`canUseWASM`).

The package compiles its module when imported, which the renderer's CSP refused under `script-src 'self'`. `script-src` now adds `'wasm-unsafe-eval'`. It permits compiling and instantiating WebAssembly only: script still loads only from the app, and `eval` and `new Function` stay blocked, unlike `'unsafe-eval'`. The alternative was highlighting in a worker, whose script from `file://` doesn't inherit the page's meta CSP. It was rejected because Pierre measures Highlights as faster on the main thread than through a worker, and because a worker would rely on that inheritance gap staying open.
