# Treat ignored files as Git does

Laneway Operations give ignored files no more protection than plain Git does. An operation that writes a rewritten tree, switches a checkout, removes a worktree, or undoes any of those may overwrite or delete ignored files in its way without listing them, asking about them, or stopping for them. Ignored files stay outside undo, as [ADR 0017](0017-recover-operations-from-git-checkpoints.md) already set out.

Laneway had grown guards on top of Git here: a collision scan before every transfer and Conflict Resolution acceptance that refused to overwrite an ignored file, an acknowledgement flag before a Worktree Removal could delete ignored files, blocks on undo and redo and on checkpoint restoration while a directory still held ignored files, the same scan before a Historical Edit entered, returned, restored a stash, or accepted a rewrite, and `--no-overwrite-ignore` on Laneway's own checkouts. Each one listed ignored paths, and on a repository with 111,000 of them the scan before acceptance ran for minutes and looked like a hang. The scan had been optimised once for transfers and still lingered in its original form elsewhere; the rest only ever produced refusals and prompts, since worktrees almost always hold ignored files.

The trade-off is a rare, unrecoverable loss: a personal copy at a path that a commit later tracks, or an ignored file inside a worktree being removed or undone. Git's own checkout and worktree removal lose exactly the same files, so users already expect that outcome, and a stricter Laneway would have paid for the guard on every operation while the loss remains rare. Laneway's pitch is faster, easier history manipulation; undo exists so that operations need no confirmation, not as a safety net worth slowing operations down to extend. The one confirmation that remains, before removing a worktree with Working Changes, is the deliberate exception from the Worktree Removal contract.

Consequences: operation flows never enumerate ignored files for safety checks, and an indexed or cheaper version of such a scan is not an acceptable reintroduction. A removal preview may still show a sample of the ignored files it will delete as information, since that listing collapses ignored directories and costs little.
