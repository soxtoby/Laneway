# Recover operations from Git checkpoints

Use retained commit tips and Git stashes as the general undo and recovery model for local Laneway Operations. Record where an operation started, then perform the Git change. Capture redo state when undo runs. Broad worktree and Git administrative snapshots and an exhaustive recovery phase journal make ordinary operations unnecessarily expensive.

Before changing affected refs or checkout state, retain their starting tips and identities. Use private Git stash objects to preserve staged, unstaged, and non-ignored untracked changes when an operation could overwrite them; leave working changes in place when the operation preserves them directly. Keep saved changes available until their restoration succeeds. At completion, record fingerprints for external-change detection without creating another stash or retaining the result for redo. Undo captures and retains the state it is leaving; redo uses that checkpoint and does the same in reverse. Store small operation-specific metadata for changes such as branch names, worktree paths, and checkout associations, rather than copying Git administrative files.

The common path needs a small durable starting record and completion record. Undo and interrupted-operation recovery restore the starting checkpoint through Git. Restore index entries from commits where they are known to match; use the saved stash when staging differs. Keep expected-tip checks and avoid overwriting subsequent external edits. If restoration conflicts or an unusual failure prevents automatic rollback, preserve the checkpoint and explain what remains for manual recovery. Exhaustive automatic reconstruction of every intermediate state is not a requirement.

Keep recovery objects out of ordinary ref decorations using the retention approach in [ADR 0014](0014-retain-operation-objects-in-protected-packs.md). Existing Operation History remains available through its legacy reader. Publish retains its separate receipt and remote-update contract.

This decision supersedes the general snapshot recovery model in [ADR 0011](0011-retain-worktree-state-in-operation-history.md) and the snapshot/journal requirements in [ADR 0015](0015-scope-independent-file-extraction.md). New local mutations, composition, file extraction, conflict operations, pull integration, and worktree operations use checkpoints. Legacy history remains readable and undoable through its existing snapshot implementation. The history file format and its integrity validation remain unchanged.
