# Check out Unresolved Stacks on temporary branches

An Unresolved Stack lives on a conspicuously named temporary branch such as `laneway/unresolved/<tip>/<operation-id>`, with no upstream, while its affected ordinary branches remain at their last resolved tips and private metadata records each provisional branch boundary. This lets Git and other tools handle commits, reflogs, worktrees, and branch identity normally; Laneway presents the intended identities, marks every affected Branch Node unresolved, and blocks Publish. External Git can still explicitly publish or merge the temporary branch, which is accepted in preference to the inconsistent tool behavior and recovery gaps of a detached HEAD or private symbolic ref.

## Consequences

The Unresolved Stack follows its temporary branch if another tool changes that branch's history. Laneway hides that representation from ordinary Branch Nodes and Command Lens results. Accepting the final conflict atomically advances every affected branch to its recorded provisional boundary, switches the worktree to its intended tip branch, and removes the redundant local temporary branch while leaving remote refs untouched. If an affected branch gained commits meanwhile, Laneway first replays only that new work onto the provisional stack and defers any resulting conflicts normally. If another tool switches away, Laneway preserves the branch and follows the normal column lifecycle. If another tool deletes it, Laneway requires an explicit restore or discard instead of silently recreating it. If external history brings recorded unresolved decisions onto an ordinary branch, that branch remains conflicted and Laneway blocks Publish.
