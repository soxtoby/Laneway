# Scope independent file extraction to its actual changes

Moving whole-file modifications from an unpublished commit into its own Working Changes uses a focused planner when the affected history is one unshared linear chain and no descendant touches those paths. Read the original trees and commit objects, then rewrite the chain in one native `fast-import` process. Restore the selected paths' parent blobs in each tree and the index; keep working file bytes unchanged. Preserve authors and messages and use the current committer identity. Commit hooks, signing, published/shared history, merges, additions, deletions, renames, staged selected changes, and unsupported metadata continue through the general planner.

Recovery snapshots declare an optional working-file scope. They still retain the complete index, Git administration, and relevant refs, but capture only working files the focused operation can affect. The scope participates in snapshot identity and survives capture, verification, undo, and redo. Unrelated working edits no longer prevent replay or get overwritten. Existing snapshots keep their original identities and full-worktree behavior.

The renderer submits composition through `local-transfer`. This command prepares under the mutation lock and immediately applies an eligible focused extraction with that same preparation. Otherwise it returns an ordinary preview; the existing confirmation/token flow remains in place. Explicit `local-preview` stays a preview, and `local` still requires its expected token. This removes duplicate preparation and a second engine invocation without bypassing published-history, conflict, hook, or stale-state checks. HEAD snapshot blobs are read once per operation and shared between its before/after retention passes.

The recovery journal remains intact. A disposable checkpoint records a fully validated, finalized journal prefix and its SHA-256 digest. Each command hashes the historical bytes before reusing the checkpoint, validates new records normally, and rejects duplicate executions across the boundary. Changed historical bytes or damaged checkpoints force full validation; pending recovery is never cached. Operation History events are parsed once per locked command.

These changes reduce redundant repository-wide work, but do not promise subsecond completion. The one-shot engine protocol, first-time pack retention, and full Branch Graph/Working Changes refresh remain measurable parts of a transfer.
